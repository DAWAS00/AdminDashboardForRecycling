🔗 Key Integration Points — How to Implement

Flutter App → Supabase

supabase_flutter SDK handles auth, database reads/writes, and realtime subscriptions. Riders broadcast GPS via deliveries table updates. RLS ensures each user only sees their own data.

Super Pays → Supabase

REST API integration from mobile app. After payment completes, Super Pays fires a webhook to a Supabase Edge Function. That function verifies the signature and writes to payments + updates orders.payment_status. PCI-DSS compliant — card data never touches Supabase.

Admin Dashboard → Supabase

Dashboard reads via service_role key (bypasses RLS for admin access). Realtime subscription on deliveries drives the live GPS map. Admin writes (rider assignment, hub management) call Edge Functions that enforce business rules before updating the DB.

Next Implementation Step

Replace RIDERS in constants.ts with a Supabase hook:
supabase.from('deliveries').select('*, users(*), orders(*)')
Then subscribe to changes: .on('UPDATE', payload => setRiders(...))
This makes the Live Map truly real-time with zero polling.

🔒

Security:  JWT tokens from Supabase Auth flow to all services  |  RLS policies enforce role-based data access per user  |  Super Pays is PCI-DSS compliant — no card data stored in Supabase  |  Admin Dashboard uses service_role key server-side only — never exposed to browser
